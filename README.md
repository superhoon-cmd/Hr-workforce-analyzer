# HR Workforce Analyzer

## 팀별 후보모델 V2 (2026-10-15)

기존 실행 명령으로 시작한 후 화면 상단의 **새 팀별 후보모델 1·2·3 및 자동 알고리즘 선택**을
누르거나 왼쪽 페이지 메뉴에서 `2_team_models`를 선택하세요. 기존 프로젝트 CSV 분석은 유지됩니다.
V2 화면에는 세 개의 합성 CSV 다운로드, 실제 CSV 업로드, 월 선택, 모델별 결과와 평가 이력 다운로드가 있습니다.
상세 입력·알고리즘·판단 유보 규칙은 [TEAM_MODELS.md](TEAM_MODELS.md)를 보세요.

- **모델 1:** 정상근무시간·휴가·관측 OT를 사용한 시간 환산(미래 업무수요/최소인원 아님).
- **모델 2:** Cell/Pack별 표준화 + L1 정규화 선형 분위수 회귀(P10/P50/P90),
  가까운 안정운영 사례의 실제 분위수와 함께 표시. 현재 HC/배정 FTE를 입력으로 재사용하지 않습니다.
- **모델 3 OT:** 이전월 유지, Ridge, Random Forest, XGBoost를 모두 평가하여 MAE로 선택.
- **모델 3 Gate:** 과거 지연빈도, Logistic, Random Forest, XGBoost를 모두 평가하여 Brier로 선택.
- 예측월보다 **이전**의 공통 시간순 검증 결과로만 선택합니다. 현재 월 정답을 본 뒤 해당 월
  예측을 교체하지 않습니다. 기준모델이 더 좋으면 기준모델을 사용합니다.
- 최신 관측월 다음 달의 정답 없는 예측도 제공합니다. 기존 7~9월 평가 제한은 V2에 적용되지 않습니다.

V2는 회사 데이터로 검증되지 않았습니다. 퇴직사유, 품질, 인력 임계점의 인과추정, ROI 최적화는
이번 알고리즘 구현에 포함하지 않았습니다. 인원범위는 경험적 참고치이며 자동 채용·감축 수치가 아닙니다.

## 기존 프로젝트 분석 화면

CSV로 프로젝트별 업무부담과 상대적인 인력 불균형 신호를 분석하고 다음 달 OT를 예측합니다.
적정인원 정답을 가정하지 않으며 필요 인원·부족 FTE·채용/감축 수치를 산출하지 않습니다.
Python 3.12, Streamlit, Random Forest, XGBoost를 사용합니다.

## 실행

```bash
cd /workspace/Hr-workforce-analyzer
UV_CACHE_DIR=/workspace/.cache/uv uv venv .venv
UV_CACHE_DIR=/workspace/.cache/uv uv pip sync --python .venv/bin/python --require-hashes requirements.lock
.venv/bin/python sample_data.py
.venv/bin/python -m streamlit run app.py --server.address 0.0.0.0 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

검증: `.venv/bin/python -m pytest -q`. 샘플 생성 명령은 `data/sample.csv`를 덮어씁니다.
화면에서도 샘플을 생성·다운로드할 수 있으며 업로드 파일을 우선 분석합니다.

## 입력 계약

열 이름은 `sample_data.py`의 `COLUMNS`와 일치해야 합니다. UTF-8 BOM을 권장합니다.
직원·월·프로젝트마다 한 행이며 직원·월별 업무비중 합계는 100%입니다.
팀은 직원 소속이며 이름·팀·역량·OT·중앙성·메일량은 같은 직원·월의 프로젝트 행에 동일하게 반복합니다.
OT는 직원 월간 시간, 메일량은 월간 건수입니다. 난이도·역량·Gate는 1~5, 중앙성은 0~1입니다.
Gate 완료일은 기준월 말까지 실제 관측한 날짜 또는 빈 값이며 예정일을 넣지 않습니다.
샘플은 2026년 2~9월, 500명·20팀·30프로젝트, 12,000행이며 각 직원은 3개 프로젝트에
30/40/30% 기여합니다. 시드 42의 합성 데이터이며 프로젝트와 팀은 독립 배정됩니다.

## 관측 지표와 상대적인 인력 신호

- 투입 FTE: 업무비중/100의 합계. 실제 투입량이며 적정인원 추정치가 아닙니다.
- 배분 OT: 직원 월 OT × 업무비중/100의 합계. 프로젝트 간 OT 중복 합산을 방지합니다.
- 평균 OT(시간/FTE): 배분 OT / 투입 FTE. 프로젝트 기여 비중 가중평균 OT 부담입니다.
- 전달 평균 OT와 변화: 정확히 직전 달의 같은 프로젝트를 연결합니다. 누락은 0시간으로
  단정하지 않고 빈 값으로 표시하며 ML에는 누락 여부와 함께 0으로 입력합니다.
- 기여 집중도: 최대 참여자의 프로젝트 내 기여 비중과 HHI(기여 비율 제곱 합).
  중앙성·메일량으로 개인 생산성이나 인원 정답을 생성하지 않습니다.

유사 프로젝트: 같은 월의 다른 프로젝트 중 난이도 차이 ≤1, Gate 차이 ≤1,
역량 차이 ≤0.75인 집단. 최소 3개가 필요합니다. 유사한 조건이 동일 업무규모를 보장하지는 않습니다.

| 판단 | 기본 기준 |
|---|---|
| 부족 가능성 | 투입 FTE ≤ 유사 중앙값의 90%, OT ≥20시간/FTE, 유사 OT의 125% 이상 및 5시간 이상 높음, 연속 최근 3개월 고부담 또는 매월 2시간 초과 상승 |
| 여유 가능성 | 투입 FTE ≥ 유사 중앙값의 110%, OT ≤10시간/FTE, 유사 OT 중앙값의 75% 이하(유사 중앙값 >0) |
| 판단 유보 | 유사 집단·연속 이력 부족 또는 위 복합 조건 미충족. 정상 인원 판정이 아님 |

고/저부담 기준과 최소 유사 프로젝트 수는 화면에서 조정합니다. 기준은 검토 가정이며 검증된
인력 정답이 아닙니다. 낮은 OT만으로 인력 과잉을 판단하지 않습니다. 여유 가능성은 반드시
납기·품질·산출물 확인이 필요합니다. OT가 높고 투입도 많으면 운영 문제와 수요를 구분해야 합니다.
관측 판단은 선택 월까지의 정보만 사용합니다. 미래 월 데이터를 사용하지 않습니다.

팀별로 같은 월의 실제 인원·FTE·OT와 각 판단 프로젝트에 대한 기여 비중을 표시합니다.
팀 부족 인원이나 팀 전체의 과잉/부족 판정으로 환산하지 않습니다.

## OT 예측과 월별 피드백

학습 정답 y는 실제 CSV에서 관측한 다음 달 평균 OT(시간/FTE)입니다. 가정식 FTE를 생성하거나
인원 정답으로 사용하지 않습니다. 전달 평균 OT는 ML 입력이며 임의의 FTE 절편을 더하지 않습니다.

입력 X: 직전월의 투입 FTE, 평균 OT, 전달 평균 OT, 누락 여부, OT 변화, 난이도·Gate·역량,
중앙성·메일량 가중평균, 완료일 기록 비중, 최대 기여 비중과 HHI입니다.

7월: 2→3, 3→4, 4→5, 5→6월 관측 OT로 학습하고 6월 입력으로 7월을 예측합니다.
8월 후보: 6→7월 관측 학습 쌍을 추가하여 누적 학습하고 7월 입력으로 예측합니다.
9월 후보: 7→8월 학습 쌍을 추가하여 누적 학습하고 8월 입력으로 예측합니다.
CSV에 더 오래된 월이 있으면 해당 이력도 포함합니다. 최근 3개월 제한은 ML 학습에 적용하지 않고
관측 인력 신호의 추세 점검에만 사용합니다. 연속 월 입력·정답이 모두 있는 모든 학습 쌍을 사용합니다.
예측월 입력이나 미래 완료일을 예측에 사용하지 않습니다. 예측값을 정답으로 재입력하지 않습니다.
현재는 7~9월 관측 자료가 있는 CSV에서 과거 시점을 재현하는 검증입니다.

### 모델 고정과 교체

각 ML 방법별로 초기 모델을 등록하고, 매월 전체 누적 이력으로 후보를 별도 학습합니다.
월의 예측 결과는 사전에 선택된 기존 모델로 생성합니다. 해당 월의 실제 OT를 확보한 후
기존 모델과 후보의 같은 프로젝트·같은 월 MAE를 비교하여 후보가 더 좋을 때만 교체합니다.
기본 최소 개선 폭은 0이며 동일하거나 나빠지면 기존 모델의 학습된 파라미터를 유지합니다.
화면에서 최소 개선 폭을 늘려 작은 오차 개선에 따른 교체를 제한할 수 있습니다.
교체 결정은 다음 달 예측부터 적용하며 이미 생성한 해당 월 예측을 후보 결과로 덮어쓰지 않습니다.
서로 다른 월의 오차는 예측 난이도 차이가 있으므로 직접 모델 교체 기준으로 삼지 않습니다.

월별 검증 표에는 실제 모델의 학습량, 전체 후보 학습량, 기존/후보 MAE, 유지/교체 결정,
결정 적용 월과 학습 범위를 표시합니다. 최종 선택된 모델은
프로젝트 폴더의 `.cache/models/{random_forest,xgboost}.joblib`에,
학습 범위는 같은 폴더의 `metadata.json`에 저장합니다. CSV가 바뀌면 전체 이력의 선택 과정을
다시 재현해 저장하며, 서로 다른 업로드 자료의 모델을 섞어서 불러오지는 않습니다.
모델 유지 중에도 최신 직전월 입력으로 예측하므로 예측값 자체가 고정되는 것은 아닙니다.

Random Forest·XGBoost·이전월 OT 유지 기준 모델을 같은 프로젝트·월에서 비교합니다.
MAE/RMSE 단위는 시간/FTE이며 적정인원 판단 정확도가 아닙니다. 신규·중단 프로젝트는
연속 월 평가에서 제외될 수 있으며 화면에 포함·제외 건수와 프로젝트를 표시합니다.
모델 차이는 신뢰구간이 아니며 재학습이 항상 성능을 개선하지 않습니다.

## 한계

업무 수요·성과 정보가 부족하여 절대 적정인원이나 인원 변경의 인과 효과를 판단할 수 없습니다.
계획/실적 공수, 목표/실제 완료일, 산출물 수량, 품질·재작업 등의 독립적 자료가 추가로 필요합니다.
Gate 완료일만으로 납기 준수 여부를 판단할 수 없습니다. 합성 데이터 성능은 실데이터 정확도를
입증하지 않습니다. 업로드 데이터는 외부 API로 전송하지 않지만 서버 메모리 캐시에 보관됩니다.
인증은 구현하지 않았으므로 실제 직원 정보의 운영 배포에는 접근 제어가 필요합니다.

## 회사 PC에서 실행

Python 3.12를 설치하고 터미널에서 `python --version`(Windows) 또는
`python3 --version`(macOS/Linux)이 동작하도록 준비하세요.
초기 설치에는 PyPI 패키지를 다운로드할 네트워크 접근이 필요합니다.
ZIP을 압축 해제하거나 GitHub 저장소를 내려받은 뒤:

- Windows: `run_windows.bat` 실행
- macOS/Linux: 프로젝트 폴더에서 `bash run_local.sh` 실행

시작 파일은 가상환경과 패키지를 준비하고 Streamlit을 실행합니다. 터미널에 표시되는
로컬 주소를 회사 PC의 브라우저에서 여세요. 종료는 터미널에서 Ctrl+C입니다.
처음에는 화면의 합성 샘플로 확인한 뒤 실제 CSV를 업로드하세요.
실행에 API 키나 외부 서비스 계정은 필요하지 않습니다.

회사 PC용 시작 파일은 운영체제에 맞는 패키지를 선택하도록 `requirements.txt`를 사용합니다.
`requirements.lock`은 이 클라우드 Linux 환경에서 검증한 고정 설치 파일이며 Linux용 NCCL을
포함하므로 Windows/macOS 설치에는 사용하지 마세요. Windows/macOS 실제 실행은 아직 검증하지 않았습니다.
실제 직원 데이터·모델·가상환경을 GitHub에 올리지 않도록 `.gitignore`로 제외합니다.
첨부 ZIP의 CSV는 모두 합성 샘플과 그 실행 결과이며 실제 직원 정보가 아닙니다.


### 개발조직 FTE 한도 입력

메인 화면의 **개발조직 FTE 한도 · 직접 입력/엑셀 업로드**에서 별도 원자료 없이 월별 프로젝트 투입량과 한도를 비교할 수 있습니다. 개발조직 소속의 참여율 합산 FTE만 입력합니다. 화면 직접 입력, `.xlsx`/CSV 업로드, 프로젝트별 한도 우선 적용, 초과량 및 결과 다운로드를 지원합니다. 상세 입력 형식은 [TEAM_MODELS.md](TEAM_MODELS.md)를 확인하세요.
